# 对话内容记录 实现计划

> **⚠️ v1.2 变更注记（2026-08-02）：** 本计划为 v1.0 实施快照，其中"注册 `/api/conversation/` 管理员路由组""向管理员提供查询"等描述已在 v1.2 变更：管理员后台查询入口移除，查询通道收敛为 `/api/conversation-log` 单一集成密钥入口（`middleware.ConversationLogAuth()` + 环境变量 `CONVERSATION_LOG_INTEGRATION_KEY`），并新增 `middleware/conversation_log_auth.go` 与 `main.go` 启动校验。当前权威以 `01_功能需求规格说明书.md` v1.2 与 `03_api_interface.md` 为准；下文任务步骤（T7 注册 AdminAuth 路由、BR3/BR6 验收）保留作历史记录，不再适用。

> **目标：** 在 relay 中转链路上以最小侵入方式捕获请求与响应明文，按会话聚合入库 ClickHouse 日志库，向授权的外部平台提供完整多轮对话查询能力。
> **架构：** 新增一个挂于 relay 路由分组的 gin middleware 与一套查询 API。middleware 同步段只捕获纯值（请求/响应字节 + context 标量），`gopool.Go` 异步闭包内完成协议解析、启发式会话识别、轮次写库；查询侧按 `created_at, request_id` 升序拼接完整对话。仅改动 `router/relay-router.go` 与 `router/api-router.go` 各一处，不碰任何中转 handler、relay 流程与 RelayInfo。
> **技术栈：** Go 1.22+、Gin、GORM v2、ClickHouse 日志库（`LOG_SQL_DSN`）、go-redis（会话缓存）、gopool（异步编排）、go-i18n（错误信息）。

- [x] **T2: service 层协议消息解析与用量解析**

  **文件：**
  - 创建：`service/conversation.go`
  - 测试：`service/conversation_test.go`（由实现者按 TDD 指导创建）

  **契约：**
  - 类型与函数签名：
    ```go
    package service

    // MsgPart 消息片段，kind 区分 text/tool_use/tool_result。
    type MsgPart struct {
        Role string `json:"role"` // user / assistant / tool / system
        Kind string `json:"kind"` // text / tool_use / tool_result
        Text string `json:"text"`
    }

    // parseRequestMessages 按 path 定协议，把请求体 messages 归一化成 []MsgPart。
    func parseRequestMessages(path string, body []byte) ([]MsgPart, error)

    // parseAssistantContent 输出同结构 []MsgPart：text 段标 Kind=text，
    // function_call/tool_use 标 Kind=tool_use。非流式解析 JSON（common.Unmarshal），
    // 流式逐行扫描 SSE（仿 relay/helper/stream_scanner.go）。
    func parseAssistantContent(path string, isStream bool, respBytes []byte) []MsgPart

    // parseUsage 从响应字节解析 prompt/completion tokens，本表 token 唯一来源。
    func parseUsage(path string, isStream bool, respBytes []byte) (promptTokens, completionTokens int)
    ```
  - 关键逻辑：
    - `parseRequestMessages`：按 path 分支定协议。OpenAI（`/v1/chat/completions`、`/v1/completions`）解析 `messages[]`，`role=tool` 标 `Kind=tool_result`；OpenAI Responses 路径（`/v1/responses`、`/v1/responses/compact`）经 `parseOpenAIResponsesInput` 解析 `input[]` 而非 `messages`（真实 API 无 messages 字段）：input 为 string 记 user text，`[]any` 元素 string 记 user text、map 取 role 与 content 文本，role=tool 标 `Kind=tool_result`；Claude（`/v1/messages`）解析 `messages[]`，`user` role 的 `content[]` 中 `type=tool_result` block 标 `Kind=tool_result`；Gemini（后缀 `:generateContent`/`:streamGenerateContent`）解析 `contents[]`。使用 `common.Unmarshal`，禁止直接调用 `encoding/json`。解析失败返回 error。
    - `parseAssistantContent`：非流式按 path 解析 JSON；流式逐行扫描 SSE（跳过 `event:` 行、剥 `data:` 前缀、跳过 `[DONE]`）。按协议分派增量位置：OpenAI chat/completions 载荷无 type，text 取 `choices[].delta.content/reasoning_content`，工具取 `delta.tool_calls[].function.name/arguments`（text 存工具名与入参紧凑表示，如 `get_weather({"city":"北京"})`）；OpenAI Responses 按事件类型，text 取 `response.output_text.delta`，工具取 `response.output_item.added(function_call)` 与 `response.function_call_arguments.delta`；Claude 按 `content_block_delta` 分派，工具参数增量在 `delta.type="input_json_delta"` 的 `partial_json`；Gemini 解析 `candidates[].content.parts[]` 与 `functionCall`。错误响应（上游 4xx/5xx JSON）无消息体时记空 `[]MsgPart`。
    - `parseUsage`：OpenAI 非流式取顶层 `usage`；流式取末个带 `usage` 的 chunk（无则记 0）；Responses 流式取 `response.completed` 事件的 `Response.Usage`；Claude 非流式取顶层 `usage`，流式合并 `message_start` 与 `message_delta` 两处 `usage.input_tokens/output_tokens`；Gemini 取 `usageMetadata`，流式取末个带 `usageMetadata` 的 chunk。只用响应字节，不做计费运算。
  - 协议路径常量：抽为包级常量（`openAIProtocol`、`claudeProtocol`、`geminiProtocol`）或复用 path 分支 helper，保证 T3/T4 复用同一协议判定逻辑。

  **验收锚点：**
  - 核心断言（表驱动，场景明确、预期值具体）：
    - `parseRequestMessages("/v1/chat/completions", body含role=tool消息)` → 该元素 `Kind == "tool_result"`、`Role == "tool"`

- [x] **T3: service 层启发式会话识别**

  **文件：**
  - 修改：`service/conversation.go`
  - 测试：`service/conversation_test.go`（由实现者按 TDD 指导创建）

  **契约：**
  - 函数签名：
    ```go
    package service

    // fingerprintMessages 对 []MsgPart 的 role+kind+text 整体 JSON 序列化做 sha256
    // 全字段指纹，不截断。nil 归一化为空切片（保证空首轮与续链空前缀指纹一致）。
    func fingerprintMessages(parts []MsgPart) string

    // sessionSlot 一个 token 下单会话的续链状态：Fingerprint 为上一轮 requestParts
    // 全字段指纹，Count 为上一轮条数，ActiveTime 为上一轮活跃 unix 时间戳。
    type sessionSlot struct {
        Fingerprint string
        SessionKey  string
        Count       int
        ActiveTime  int64
    }

    // sessionMultiSlot 单 token 多会话槽位列表，退化模式下用 sync.Mutex 保护读改写。
    type sessionMultiSlot struct {
        mu    sync.Mutex
        slots []sessionSlot
    }

    // resolveSessionKey 会话指纹到 sessionKey 的映射，返回是否新建会话（isNew 同时
    // 驱动存储全量/增量）。Redis 可用走多槽列表（跨实例共享）；不可用退化进程内 map。
    func resolveSessionKey(tokenID int, requestParts []MsgPart) (sessionKey string, isNew bool)

    // matchSessionSlots 在多槽列表上做续链匹配：prune 超时槽，找到条数增长且前缀
    // 指纹命中的槽则续链刷新，全不命中追加新槽并按上限淘汰。纯函数。
    func matchSessionSlots(slots []sessionSlot, requestParts []MsgPart, now int64) (sessionKey string, isNew bool, updated []sessionSlot)

    // loadSessionSlots/saveSessionSlots Redis 多槽列表的 JSON GET/SET（TTL 30min）。
    func loadSessionSlots(tokenID int) []sessionSlot
    func saveSessionSlots(tokenID int, slots []sessionSlot) error

    // redisExpire 保留供 V2 Lua 原子化续期；V1 续期由 saveSessionSlots 的 SET-with-TTL 天然完成。
    func redisExpire(key string, ttl time.Duration) error
    ```
  - 关键逻辑：
    - 全字段指纹 `fingerprintMessages(parts)`：对 `[]MsgPart` 的 role+kind+text 整体 `common.Marshal` 序列化做 sha256，不截断；`nil` 归一化为空切片，保证空首轮与续链空前缀（`requestParts[:0]`）指纹一致。同 token 不同会话（主对话 + 技能/标题生成）请求体不同即指纹不同，天然不误并。
    - `resolveSessionKey`：构造缓存键 `conv:session:{token_id}`（按 token 分桶，键内不再含指纹），TTL 30min。先判断 `common.RedisEnabled`：不可用走 `resolveSessionKeyLocal` 退化路径（进程内 `sync.Map`，value 为 `*sessionMultiSlot`，`sync.Mutex` 保护读改写，首例退化经 `common.SysError` 标注）；Redis 可用时 `loadSessionSlots` 读多槽 JSON 数组，`matchSessionSlots` 续链匹配或追加新槽，`saveSessionSlots` 写回（SET-with-TTL 天然续期）。Redis 运行期出错（连接失败/超时）捕获链路不中断，按新会话回退生成 sessionKey，`common.SysError` 记录。sessionKey 用 `common.NewRequestId()` 生成。
    - `matchSessionSlots(slots, requestParts, now)` 纯函数：先 prune 超时槽（`ActiveTime ≤ now-30min`）；遍历各槽，续链命中条件为 `len(requestParts) > slot.Count`（条数严格增长）且 `fingerprintMessages(requestParts[:slot.Count]) == slot.Fingerprint`（本轮请求体完整包含上一轮 request 侧内容）→ 续链该槽，刷新 `{Fingerprint=本轮全量指纹, Count=本轮条数, ActiveTime=now}`；全不命中追加新槽 `{Fingerprint=本轮全量, SessionKey=新生成, Count=本轮条数, ActiveTime=now}`；槽位上限 32，超限按 ActiveTime 最早淘汰。
    - 键构建用 `strconv.Itoa(tokenID)`。

  **验收锚点：**
  - 核心断言：
