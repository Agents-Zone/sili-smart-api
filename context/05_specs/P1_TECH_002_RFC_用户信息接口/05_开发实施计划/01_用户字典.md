# 用户信息字典查询接口 实现计划

> **目标：** 在 `/api/conversation-log` 集成密钥套件中新增 `GET /users` 用户信息字典查询接口，按用户聚合返回启用状态用户的 username 与名下启用 token 的 token_name。
> **架构：** 复用现有 `conversationLogRoute` 路由组与 `ConversationLogAuth` 中间件，不引入新依赖、不改 DDL。model 层以两段式查询主库 `users`/`tokens` 表（先分页取用户、再批量取名下 token、Go 内存聚合），controller 层复用 `common.GetPageQuery`/`PageInfo`/`ApiSuccess` 响应封装。
> **技术栈：** Go 1.22+ / Gin / GORM v2 / go-i18n / testify

- [x] **T1: model 层 DTO 类型与 ListConversationUsers 查询函数**

  **文件：**
  - 修改：`model/conversation.go`（在现有 `GetConversationTurns` 之后追加）
  - 测试：`model/conversation_users_test.go`（由实现者按 TDD 指导创建，`package model`）

  **契约：**

  签名（三个 DTO 严格遵循 04_model_interface.md §聚合响应结构 / SSOT §2.3）：

  ```go
  package model

  type ConversationToken struct {
      TokenID   int    `json:"token_id"`
      TokenName string `json:"token_name"`
  }

  type ConversationUserSummary struct {
      UserID   int                 `json:"user_id"`
      Username string              `json:"username"`
      Tokens   []ConversationToken `json:"tokens"`
  }

  type ConversationUserQueryParams struct {
      Username  string
      TokenName string
  }

  // ListConversationUsers 按用户聚合分页返回启用状态用户的 username 与名下启用 token_name。
  // 返回 ([]ConversationUserSummary, int64, error)，int64 为满足条件的用户总数。
  func ListConversationUsers(params *ConversationUserQueryParams, page, pageSize int) ([]ConversationUserSummary, int64, error)
  ```

  关键逻辑（依据 04_model_interface.md §GORM 实现方案，两段式三库兼容，全程用主库 `DB` 句柄，不碰 `LOG_DB`）：

  1. 入口防御：`if page < 1 { page = 1 }`。
  2. 用户分页查询（含 token_name 资格收口）：基链 `DB.Model(&User{}).Where("status = ?", common.UserStatusEnabled)`；`params.Username != ""` 时追加 `.Where("username LIKE ?", "%"+params.Username+"%")`；`params.TokenName != ""` 时追加 `.Where("id IN (?)", DB.Model(&Token{}).Select("user_id").Where("status = ?", common.UserStatusEnabled).Where("name LIKE ?", "%"+params.TokenName+"%"))`，把用户集合收口为名下至少含一个匹配启用 token 的用户。先 `.Count(&total)` 取总数，再 `.Select("id, username").Order("id asc").Limit(pageSize).Offset((page-1)*pageSize)`，Find 到包内私有投影结构体 `type convUserRow struct { Id int; Username string }`。
  3. 令牌批量查询：收集本页 `userIDs`；若为空直接返回空 summary 切片、`total`、`nil`。否则 `DB.Model(&Token{}).Where("user_id IN ?", userIDs).Where("status = ?", common.UserStatusEnabled)`，`params.TokenName != ""` 时追加 `.Where("name LIKE ?", "%"+params.TokenName+"%")`，`.Select("id, user_id, name").Order("user_id asc, id asc")`，Find 到包内私有投影结构体 `type convTokenRow struct { Id int; UserId int; Name string }`。
  4. 内存聚合：`result := make([]ConversationUserSummary, 0, len(userRows))`，每个用户 `Tokens` 初始化为 `[]ConversationToken{}`（非 nil，保证 JSON 序列化为 `[]` 而非 `null`）；建 `userID → result 下标` 的 map；按 `userRows` 顺序 append 用户行，按 `tkRows` 顺序把 token 挂到对应用户（`tkRows` 已按 `user_id asc, id asc` 排序，每用户 token 自然按 `token_id` 升序）。
  5. 软删除：`User`/`Token` 均声明 `gorm.DeletedAt`，GORM 自动追加 `deleted_at IS NULL`，无需手写过滤。
  6. 字段最小化：两个投影结构体只声明 `id`/`username` 与 `id`/`user_id`/`name`，从结构上保证不读 `tokens.key`、`users.password`/`email`/`quota` 等敏感列（04 §字段最小化映射、SSOT §3.2）。

  依赖：`model`（`DB`、`User`、`Token`）、`common`（`UserStatusEnabled`）；`github.com/QuantumNous/new-api/common` 在 model 包内已有 import。

  **验收锚点：**

## 备注：与 03 文档 HTTP 状态码的取舍

03_api_interface.md 错误码表将查询参数非法、数据库错误标为 HTTP 400/500。项目 common 层所有业务错误响应（`ApiErrorI18n`/`ApiError`/`ApiErrorMsg`）统一返回 HTTP 200 + `success:false`，现有会话列表 `ListConversations` 亦然；SSOT §2.4 多处要求本接口「错误码与会话列表/详情一致」。两者冲突时，以「与会话列表实际行为一致」为准：本接口业务错误统一 HTTP 200 + `success:false`（数据库错误用 `i18n.MsgDatabaseError`），不照 03 文档字面写 400/500。鉴权错误 401/403 由 `ConversationLogAuth` 中间件 `c.AbortWithStatusJSON` 返回，复用现状不改。
