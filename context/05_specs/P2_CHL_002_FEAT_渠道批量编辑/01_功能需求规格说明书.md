# 功能需求规格说明书

## 1. 概述

### 1.1 功能背景

渠道管理是本系统的核心运营能力。当前单个渠道的编辑通过右侧抽屉完成，已有批量模式支持批量启用、禁用、设置标签、删除，但缺少批量编辑渠道字段的能力。当运营人员需要统一调整一批渠道的分组、模型列表、权重、优先级等配置时，只能逐个打开编辑抽屉重复操作，效率低且易出错。

### 1.2 本功能业务目标

1. 支持对勾选的多条渠道一次性统一修改字段，填写了的字段统一替换，未填写的字段保持各渠道原值
2. 复用现有批量勾选交互，与批量启用/禁用/设标签/删除保持一致的入口体验
3. 事务化执行，全成全败，避免批量操作导致渠道数据部分更新的不一致状态
4. 批量编辑纳入管理员审计日志，记录生效字段，保证可追溯

## 2. 角色与权限矩阵

### 2.1 数据权限（行级访问控制）

| 角色 | 数据范围 | 说明 |
|------|---------|------|
| 渠道管理员（含 ChannelWrite 权限的管理员） | 全部渠道数据 | 渠道为系统级资源，无按创建人隔离，持有对应权限的管理员可操作全部渠道 |

**数据范围说明：**
- **全部数据**：渠道管理属管理后台，仅管理员可见，无部门/个人维度隔离

### 2.2 页面访问权限

| 页面名称 | 可访问角色 | 可操作角色 | 字段级权限（如有） |
|---------|----------|----------|------------------|
| 渠道列表页（现有） | 持有 ChannelRead 权限的管理员 | 见各操作项 | 无 |
| 批量编辑抽屉（新增） | 持有 ChannelWrite 权限的管理员 | 持有 ChannelWrite 权限的管理员 | 无（表单已排除密钥等敏感字段） |

**权限说明：**
- **可访问角色**：批量编辑按钮仅对持有 ChannelWrite 权限的管理员可用，无权限时按钮禁用并提示无权限
- **可操作角色**：批量编辑提交与单个编辑一致，使用 ChannelWrite 权限级别；表单已限定为仅含 ChannelWrite 可编辑的非敏感字段
- 批量编辑表单仅包含非敏感字段，不涉及 ChannelSensitiveWrite 权限判定（与系统渠道编辑的敏感字段鉴权契约对齐：修改密钥、类型、base_url、param_override 等敏感字段需 ChannelSensitiveWrite，故此类字段均不在批量编辑表单中提供，见 4.2.2 D 区排除字段）

## 3. 页面与功能总览

### 3.1 页面清单

| 序号 | 页面名称 | 页面形式 | 职责说明 | 包含功能 |
|-----|---------|---------|---------|---------|
| 1 | 渠道列表页 | 独立页面（现有，无结构性改动） | 渠道数据展示与批量操作入口 | 批量模式勾选、批量工具栏（新增批量编辑按钮） |
| 2 | 批量编辑抽屉 | 抽屉（新增） | 对勾选渠道批量统一编辑字段 | 分区表单填写、提交前校验、二次确认、批量保存 |
| 3 | 批量编辑确认弹窗 | 弹窗对话框（新增） | 提交前的操作确认与摘要展示 | 确认执行、取消 |

### 3.2 页面跳转流程

```
[入口：渠道列表页] → 开启批量模式 → 勾选渠道 → 批量工具栏出现 → 点击[批量编辑] → [批量编辑抽屉]
                                                                              ↓
                                                                    填写字段 → 点击[保存]
                                                                              ↓
                                                                   [批量编辑确认弹窗] → 确认 → 执行
                                                                              ↓
                                                                    成功 → 关闭抽屉 → 刷新列表 + 清除勾选
```

**流程说明：**
1. 管理员在渠道列表页开启批量模式（现有开关），勾选目标渠道
2. 批量工具栏出现后，点击批量编辑按钮打开批量编辑抽屉，抽屉顶部展示已选渠道数量
3. 管理员填写需要统一修改的字段，未填写的字段跳过
4. 点击保存，弹出确认弹窗展示将修改的渠道数量与生效字段列表
5. 确认后关闭确认弹窗，抽屉保持打开并进入提交中状态（保存按钮 loading），后端事务化执行；成功后关闭抽屉、刷新渠道列表与缓存、清除勾选；失败时抽屉内展示失败渠道列表并保留已填内容（见 4.2.4 规则3、规则6）

### 4.2 页面 2：批量编辑抽屉（新增）

#### 4.2.1 页面概述

**页面形式：**参见第3.1节页面清单

**页面职责：**对勾选的多条渠道统一编辑字段。表单分区沿用单个编辑抽屉的结构，字段全部留空表示保持原值（生效语义见 4.2.4 规则1）。

#### 4.2.2 涉及字段

> 字段校验矩阵：批量编辑表单所有字段均为非必填。以下按分区列出可编辑字段。字段生效语义统一见 4.2.4 规则1，校验仅在字段已填写时触发。

##### A. 基础信息区

| 字段 | 必填 | 长度 | 格式 | 范围 | 唯一 | 示例 | 其他 |
|:--|:--|:--|:--|:--|:--|:--|:--|
| 分组（group） | × | (0,64] | 逗号分隔的分组串 | - | × | default,vip | 可多选，选项来自系统分组列表 |
| 标签（tag） | × | (0,191] | 文本 | - | × | 生产渠道 | 填写即统一替换；留空跳过（不清空，清空走现有批量设标签留空逻辑）；上限对齐 channels.tag 列现状 varchar(191) |
| 备注（remark） | × | (0,255] | 文本 | - | × | 临时降级渠道 | 可编辑/可显示 |

##### B. 模型区

| 字段 | 必填 | 长度 | 格式 | 范围 | 唯一 | 示例 | 其他 |
|:--|:--|:--|:--|:--|:--|:--|:--|
| 模型列表（models） | × | - | 模型名逗号分隔串 | - | × | gpt-4o,claude-3-5-sonnet | 语义为统一替换，不支持追加；支持从模型选择器选取或手动输入；单个模型名 ≤255（防护 abilities.model 列长 varchar(255)） |
| 模型重定向（model_mapping） | × | - | JSON 对象 | - | × | {"gpt-4o":"gpt-4o-mini"} | 已填写时须为合法 JSON 对象，提交前校验 |

##### C. 高级设置区

| 字段 | 必填 | 长度 | 格式 | 范围 | 唯一 | 示例 | 其他 |
|:--|:--|:--|:--|:--|:--|:--|:--|
| 权重（weight） | × | - | 整数 | 0-4294967295 | × | 10 | 未填写跳过 |
| 优先级（priority） | × | - | 整数 | -9223372036854775808-9223372036854775807 | × | 0 | 未填写跳过 |
| 测试模型（test_model） | × | (0,255] | 文本 | - | × | gpt-4o | 未填写跳过；统一替换各渠道的渠道测试模型 |
| 自动封禁（auto_ban） | × | - | 三态选择 | 不变/启用/停用 | × | 不变 | 默认不变（即跳过，对应空即跳过语义）；选择启用或停用时统一替换各渠道的自动封禁开关 |

##### D. 排除字段（表单中不出现）

以下字段在批量编辑表单中不提供：名称（name）、密钥（key）、渠道类型（type）、代理地址（proxy）、状态码映射（status_code_mapping）、多 Key 模式开关（multi_key_mode）、多 Key 密钥模式（key_mode）、其他信息（other_info）与多 Key 运行状态（channel_info）。排除原因分两类：其一为系统鉴权契约中的敏感字段（key、type、base_url、openai_organization、其他参数 other、渠道额外设置 setting、代理地址 proxy、参数覆写 param_override、请求头覆写 header_override、其他设置 settings、key_mode），修改需 ChannelSensitiveWrite，仅支持在单个编辑抽屉中操作。其中 proxy 是渠道额外设置（setting）的组成部分，在 `controller/channel_authz.go` 的敏感字段判定中走 fail-closed 分支归入敏感类，与 setting 同源。其二为设计取舍（name、status_code_mapping、multi_key_mode、other_info、channel_info），这五项虽属 ChannelWrite 可编辑范围，但为控制批量影响面、避免误改唯一性标识与渠道行为配置，本功能仅开放路由类与展示类字段；其中 other_info（余额告警等服务端配置）与 channel_info（多 Key 运行状态）为服务端维护字段。此外，渠道主键 id 仅作为目标定位键（请求体 ids 的成员），不作为可编辑字段出现在表单与请求体中。

  - 触发按钮：取消

**后台自动流程（如有）：**

  - 触发时机：抽屉打开时
  - 说明：抽屉顶部展示当前勾选的渠道数量，打开期间勾选关系不可变更

#### 4.2.4 业务规则

- **规则1：空即跳过**
  - 规则描述：批量编辑表单全部字段默认留空。已填写的字段对全部选中渠道统一替换为所填值；未填写的字段保持各渠道原值，不做任何变更
  - 触发条件：提交批量编辑时按字段逐一生效
  - 约束说明：留空语义为跳过而非清空，任何字段都无法通过批量编辑清空为空值（清空标签走现有批量设标签的留空逻辑）

- **规则2：类型相关字段降级**
  - 规则描述：允许勾选不同类型的渠道混合批量编辑。当前表单字段均为类型无关字段；类型专属配置（如 Azure API 版本、Vertex 认证方式等）属敏感/类型绑定字段，已在 4.2.2 D 区排除清单中，不支持批量编辑。若后续表单引入类型相关字段，须在勾选渠道类型不一致时隐藏或禁用该字段，并在字段位置提示仅同类型渠道可编辑
  - 触发条件：抽屉打开时根据勾选渠道的类型集合判定
  - 约束说明：类型集合唯一时正常展示类型相关字段；类型集合大于 1 时该类字段不参与本次批量编辑（为后续扩展保留的约束）

- **规则3：事务全成全败**
  - 规则描述：后端在单个事务内逐条更新选中渠道（含各渠道的 abilities 路由索引重建），任一渠道更新失败即回滚全部，接口返回失败并附带触发回滚的渠道 ID 与失败原因；串行执行遇首个失败即回滚，故失败渠道恒为 1 条，响应仍以数组承载，前端在抽屉内以列表展示
  - 触发条件：批量编辑提交执行时
  - 约束说明：成功即全部成功；失败时所有渠道保持编辑前状态；重试为全量重试；单次批量上限 200 条（本功能新增上限），超出时前端拦截并提示分批操作；ids 中已不存在的渠道（如并发删除）跳过不视为失败，成功响应的更新数量返回实际更新数

- **规则4：渠道能力与独占索引同步**
  - 触发条件：批量编辑涉及模型列表、分组、权重、优先级、标签等路由相关字段变更时（标签参与 abilities 行冗余，变更同样触发重建）
  - 规则描述：abilities 路由索引重建在批量编辑事务内逐渠道执行，失败即整体回滚（与规则3 同一口径）；事务提交后调用 P2_CHL_001 的按渠道清理能力，对受影响渠道同批清除反向占用索引条目、最近绑定记录与该渠道仍持有的正向绑定（对齐 P2_CHL_001 的 5.2.2 第7条与 5.2.4 规则2 三批同清口径，不允许只清反向占用索引）
  - 约束说明：清理失败时重试一次，仍失败记录服务端错误日志，残留条目随 TTL 自然过期收敛（与 P2_CHL_001 的 5.2.5 异常处理语义对齐），不阻断批量编辑结果

- **规则5：审计日志**
  - 规则描述：批量编辑执行成功后记录管理员审计日志，内容包括操作类型（channel.update_batch）、渠道数量、渠道 ID 列表、生效字段列表及所填值全量（审计日志记录所填值原文，不做截断）
  - 触发条件：批量编辑事务提交成功后
  - 约束说明：复用现有 recordManageAudit 审计机制

- **规则6：成功后清理**
  - 规则描述：批量编辑成功后刷新渠道缓存与列表数据，自动清除全部行勾选，并提示成功文案（已更新 N 条渠道）
  - 触发条件：接口返回成功后
  - 约束说明：失败时保留抽屉内已填内容与勾选状态，便于修正后重试

#### 4.2.5 交互逻辑

- 抽屉打开时表单全部字段留空，抽屉内有说明文案（字段生效语义见 4.2.4 规则1）
- 模型列表支持从模型选择器多选与手动输入两种方式
- 分组为下拉多选，选项来自系统分组列表

#### 4.2.6 权限要求

参见第2.2节页面访问权限。

  - 触发方式：点击按钮
  - 权限要求：无限制
  - 加载状态：无
  - 功能说明：关闭弹窗，返回批量编辑抽屉，保留已填内容

#### 4.3.4 业务规则

- **规则1：无生效字段拦截**
  - 规则描述：所有字段均未填写时，抽屉保存按钮点击后提示至少填写一个字段，不打开确认弹窗（拦截逻辑见 4.2.3 保存批量编辑功能说明）
  - 触发条件：保存时生效字段数为 0
  - 约束说明：避免提交无意义的空批量请求

#### 4.3.5 交互逻辑

- 弹窗内容：将修改 N 条渠道 + 生效字段列表（字段名+所填值摘要），摘要超 50 字符截断显示…，悬浮展示全部

#### 4.3.6 权限要求

参见第2.2节页面访问权限。
