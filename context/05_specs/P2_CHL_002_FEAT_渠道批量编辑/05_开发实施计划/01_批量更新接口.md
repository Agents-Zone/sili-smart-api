# 渠道批量编辑 · 批量更新接口 实现计划

> **目标：** 实现 `POST /api/channel/batch/update`，在单个事务内对勾选渠道统一替换已填字段（空即跳过），重建 abilities 路由索引，提交后刷新缓存、按渠道清理独占运行时数据并记录管理审计。
> **架构：** 沿用项目现有分层（Router → Controller → Model）：参数校验与编排在 controller，事务与列白名单更新在 model，独占运行时清理复用 P2_CHL_001 的 service 层清理原语。本 Feature 无数据库结构变更，无迁移任务。
> **技术栈：** Go 1.22+、Gin、GORM v2、go-redis（HybridCache）、testify（require 做致命断言 / assert 做值检查）。

  **契约：**
  - 签名：`func ClearChannelAffinityRuntimeByChannelIDs(channelIDs []int) int`
  - 语义：对给定渠道同批清除三类运行时数据（三批同清）：该渠道仍持有的正向绑定、该渠道的反向占用索引条目、对应键的最近绑定记录。返回清除的正向绑定条数（与 `ClearChannelAffinityCacheAll() int` 的返回值口径一致：正向删除条数）。
  - 关键逻辑：
    1. 目标集合：`channelIDs` 中 `id > 0` 的去重集合；集合为空直接返回 0
    2. `keys, err := getChannelAffinityCache().Keys()`，失败记 `common.SysError` 并按空键集继续
    3. 遍历 keys：用 `strings.CutPrefix(k, channelAffinityCacheNamespace+":")` 取 suffix（空则跳过），`forward.Get(k)` 读该键绑定的渠道（传 full key，`Namespace.FullKey` 幂等，见 `pkg/cachex/namespace.go:17`）；渠道值命中目标集合时记入 `matched []string`（full key）与 `boundChannels map[string]int`（suffix→channelID）
    4. `matched` 为空返回 0
    5. 正向删除：`retryOnce(func() error { _, err := forward.DeleteMany(matched); return err })`，失败记 `common.SysError` 后**继续第 6 步**（正向残留随 TTL 收敛，方向为多清不少清）
    6. 回放：`clearExclusiveRuntimeByForwardKeys(matched, boundChannels)`（`service/channel_affinity_exclusive.go:1292`，内部按 suffix 推导指纹做 occupancy 成员级移除，并对全部 suffix 批删 lastBind，自带 retryOnce 与 SysError）
  - 边界：`boundChannels` 必须在删除正向**之前**读出（删除后 `forward.Get` 读不到值）；渠道数 0 或全为非法 id 时零副作用、不写日志
  - 依赖：`channelAffinityCacheNamespace`、`getChannelAffinityCache()`、`clearExclusiveRuntimeByForwardKeys`、`retryOnce`、`common.SysError`（均在同文件或 `service/channel_affinity.go` 内已存在，无需新增依赖）

  **验收锚点：**

    - `applyTo` 的 map 键用数据库列名（`group`/`tag`/`remark`/`models`/`model_mapping`/`weight`/`priority`/`test_model`/`auto_ban`，04 文档 4.1 映射表）；**必须走 `Updates(map[string]any)`**，因为 weight=0、priority=0、auto_ban=0 是合法生效值，struct 形式会被 GORM 静默丢弃（04 文档 3.1 业务规则）

    - abilities 重建失败时的 Reason 文案：`fmt.Sprintf("更新 abilities 失败: %v", err)`；列更新失败的 Reason 为 `err.Error()`

    - 不触碰 key/type/base_url/param_override 等敏感列，也不写 channel_info（D 区排除清单）
  - 边界：`ids` 为空时返回 `(0, nil, nil)` 且不开启事务；路由字段全未生效时跳过 abilities 重建（无变更不写入）

    ```go
    // ChannelBatchUpdateRequest 批量编辑请求体。字段全部为指针：省略或 null 即跳过，
    // 出现即生效（03 文档 1.2 空即跳过语义）。D 区排除字段不在结构体中声明，
    // 未知/排除字段经白名单 DTO 天然不解析（03 文档 2.2.9）。
    type ChannelBatchUpdateRequest struct {
        Ids          []int   `json:"ids"`
        Group        *string `json:"group"`
        Tag          *string `json:"tag"`
        Remark       *string `json:"remark"`
        Models       *string `json:"models"`
        ModelMapping *string `json:"model_mapping"`
        Weight       *int    `json:"weight"`
        Priority     *int64  `json:"priority"`
        TestModel    *string `json:"test_model"`
        AutoBan      *int    `json:"auto_ban"`
    }

    // buildBatchUpdateFields 校验并归一化请求：返回列更新字段；err 为具体失败原因。
    // 校验顺序：ids 边界 → 逐字段值域 → 生效字段数（03 文档 2.2）。
    func (r *ChannelBatchUpdateRequest) buildBatchUpdateFields() (model.ChannelBatchEditFields, error)
    ```
  - 关键逻辑（每条对应一个错误文案，与 03 文档 2.2 逐字一致）：
    - ids：`len == 0` → `参数错误`；`len > 200` → `单次批量编辑上限 200 条，请分批操作`
    - group：`strings.TrimSpace` 后为空 → 跳过；trim 后长度 `> 64` → `分组长度不能超过 64 字符`；按 `,` 拆分后存在 trim 为空的段 → `分组格式错误`；生效值写 trim 后的原串
    - tag：trim 后为空 → 跳过；trim 后长度 `> 191` → `标签长度不能超过 191 字符`
    - remark：trim 后为空 → 跳过；trim 后长度 `> 255` → `备注长度不能超过 255 字符`
    - models：trim 后为空 → 跳过；按 `,` 拆分后存在 trim 为空的段 → `模型列表格式错误`；任一段长度 `> 255` → `模型名称过长: {段原文}`（与 `validateChannel` 添加路径同口径）
    - model_mapping：trim 后为空串 → `模型重定向不能为空（如需清空请在单个编辑中操作）`；用 `common.Unmarshal` 解到 `map[string]any` 失败 → `模型重定向必须是合法的 JSON 对象`（顶层数组/标量同样拒绝）
    - weight：`*v < 0 || int64(*v) > 4294967295` → `权重必须在 0-4294967295 之间`；写入转 `*uint`
    - priority：不做范围校验（`*int64` 已覆盖声明值域）；非整数输入由 JSON 解析阶段拒绝
    - test_model：trim 后为空 → 跳过；trim 后长度 `> 255` → `测试模型长度不能超过 255 字符`
    - auto_ban：值非 `0` 且非 `1` → `自动封禁取值错误`
    - 生效字段数：上述全部字段均跳过时 → `批量编辑至少需要填写一个字段`
  - 边界：`*int` / `*int64` 精确解析，禁止经 float64 中转（03 文档 2.2.5：priority int64 全域在 2^53 以上无法被 float64 精确表示）；字符串类字段一律以 trim 后值判定与写入，保证 `"  "` 与 `""` 语义一致
