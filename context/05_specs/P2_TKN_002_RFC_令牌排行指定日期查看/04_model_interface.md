# 令牌排行指定日期查看 数据模型设计

## 基础信息

- **Feature ID**：P2_TKN_002_RFC_令牌排行指定日期查看
- **适用性**：not_applicable（无新增或变更持久化对象）
- **规格依据**：`01_功能需求规格说明书.md` §1.2 业务目标 4（数据链路零改动）；§5 非页面功能（[无变化] 聚合、权限、异常处理均同基线）；§6 数据状态定义（[无变化] 只读统计展示，无自有数据状态与状态流转）
- **模块前缀**：`tkn_analysis`（沿用基线 Feature P2_TKN_001 的分组标识）
- **数据库类型**：主库 SQLite / MySQL >= 5.7.8 / PostgreSQL >= 9.6（GORM v2；本变更无建表与迁移）
- **基线模型设计**：`../P2_TKN_001_FEAT_令牌统计分析/04_model_interface.md`（quota_data 与 tokens 的结构基线、索引说明、查询形态继续有效）

## 结论与依据

本变更为纯前端筛选扩展，指定日期模式仅改变前端传入 `GET /api/data/tokens` 的时间窗口取值，查询形态、分组方式、关联逻辑均与基线一致，无任何 DDL、DML、索引变更或迁移语句。

| 对象 | 变更类型 | 依据 |
|---|---|---|
| quota_data 表 | 无变更（只读，聚合查询与基线同形态） | 规格 §5 [无变化]、§4.1.4 规则4（自然日窗口即普通时间窗口） |
| tokens 表 | 无变更（只读，按 id IN 取 name） | 规格 §5 [无变化]，名称关联与回退同基线 |

自然日窗口最大跨度 86400 秒，复用既有 `idx_qdt_created_at` 时间过滤与 `token_id` 分组维度，无新增索引需求。
